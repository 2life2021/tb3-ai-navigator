## 2. LiDARのデータが MLP に入るまで：前処理

### 2.1 生データ
`/scan` トピックの `sensor_msgs/LaserScan` には、360個の距離 `ranges[0..359]` が入っています。Gazeboの設定は5Hz・360サンプル・0.12〜3.5m・ノイズσ=0.01mです。
- `ranges[0]` が **正面** で、インデックスが増えるほど **反時計回り、つまり左** に回ります。`ranges[90]` が真左、`ranges[270]` が真右です。
- 3.5mより遠い方向や、何もない方向は `inf` になります。

### 2.2 `clean_ranges` — common.py 21行目
`inf`・`nan`・0以下の値を3.5mに置き換え、0〜3.5mの範囲に収めます。ニューラルネットワークは `inf` を扱えないためです。

### 2.3 `scan_to_features` — common.py 28行目
360本をそのまま入力にせず、**5°ごとの72個の扇形、つまりセクタに分け、各セクタの最小距離**をとります。
- 最小値をとるのは、衝突回避では「その方向で一番近い障害物」が重要だからです。
- 最後に3.5で割って **0〜1に正規化** します。ニューラルネットワークは、入力の大きさがそろっている方が学習しやすいためです。
- 結果は **72次元のベクトル** です。例えば `feat[0]` は、0〜5°方向の最小距離を3.5で割った値です。
- v1モデル用の15°刻み24セクタにも対応しています。どちらを使うかは、モデルファイルに保存された `n_sectors` で決まります。policy.py の13行目です。

```
360本の距離 ──clean_ranges──► 0〜3.5m の360本 ──scan_to_features──► 72個の最小距離 ÷3.5 ──► MLPへ
```

## 3. ネットワーク構造：72-128-128-3 — common.py 98行目 `PolicyMLP`

```python
nn.Sequential(
    nn.Linear(72, 128), nn.ReLU(),     # 第1層: 72個の入力 → 128個のニューロン
    nn.Linear(128, 128), nn.ReLU(),    # 第2層: 128 → 128
    nn.Linear(128, 3),                 # 出力層: 128 → 3。前進・左・右のスコア
)
```

- **Linear・全結合層**: 各出力ニューロンは、入力すべてに重みを掛けて足し、バイアスを足した値 `y = Wx + b` を計算します。第1層の重み W は128×72個あります。
- **ReLU**: 負の値を0にする非線形関数 `max(0, x)` です。これがないと何層重ねても1層の線形変換と同じになり、「前方が近い **かつ** 右も近いなら左」のような組み合わせの判断を表現できません。
- **出力・ロジット**: 3つの実数のスコアです。policy.py の23行目で **softmax** を適用し、合計1の確率 `[P(前進), P(左), P(右)]` に変換します。
- **パラメータ数**: 72×128+128 + 128×128+128 + 128×3+3 = **26,243個** です。小さなモデルなので、CPUだけで走行中に推論できます。

## 4. 教師データの収集と模倣学習の仕組み

### 4.1 教師はルールで書かれている
`teacher_action_v2` は common.py の71行目にある、人間が書いた if 文です。LiDARから「正解の行動」を決めます。
1. 前方±30°の最小距離が0.55mより遠く、斜め前30〜75°と−75〜−30°が0.35mより遠ければ、前進の候補にします。ただし、真横75〜105°に0.22m未満の壁があれば、反対側へ旋回します。
2. それ以外は、左右20〜100°の平均距離が大きい方へ旋回します。

**重要**: 学習データの正解ラベルは、すべてこのルールで自動生成しています。人間が操作したデータではありません。

### 4.2 データ収集 `collect_data.py`
`on_scan` は collect_data.py の59行目にあり、`/scan` を受信するたびに約5Hzで次の処理を行います。
1. 生LiDAR 360本と、教師ルールが出した **ラベル** を記録します。
2. 実際にロボットを動かす行動を決めます。
   - 通常は、教師の行動をそのまま実行します。`--policy teacher` の場合です。
   - 確率 ε で、**わざとランダムな行動** を1〜4ステップ続けます（74行目）。教師だけでは訪れない「少し危ない状態」もデータに入り、その状態での正しい行動を学べるようにするためです。
   - DAggerモード `--policy student` では、学習済みモデルが運転し、教師はラベルを付けるだけです（78行目）。確率 β で教師が運転します。
3. 障害物に0.13m未満まで近づくか、15秒間動けなければ、`/reset_world` で初期位置へ戻します（93・99行目）。

保存されるのは、収集時の特徴量 `X`、教師ラベル `y`、生LiDAR 360本 `raw` です。**`raw` を保存してあるので、後から教師ルールを変えても、`train.py --relabel` でラベルを付け直せます。**

### 4.3 模倣学習
「LiDAR → 教師の行動」という対応を、**教師あり学習の分類問題** として学びます。写真から猫か犬かを当てる画像分類と同じ枠組みで、入力が LiDAR、クラスが3つの行動になっているだけです。

`train.py` は次の流れで学習します。
1. `raw` から特徴量を計算し、`--relabel` のときは教師ルールでラベルを付け直します。
2. 全データをシャッフルし、**80%を学習用、20%を検証用** に分けます（42行目）。検証用は学習に使わず、初めて見るデータに対する正解率を測るために使います。
3. `--augment` のときは、学習用のデータだけを増やします（51〜55行目）。
   - **左右反転** `np.roll(r[::-1], 1)`: 角度θのデータを−θへ移し、左右を入れ替えたスキャンに対して教師ルールでラベルを付け直します。
   - **ノイズ付加** `rng.normal(0, 0.02, …)`: 距離に2cm程度のランダムな揺らぎを加えます。
4. 前進が多く旋回が少ない不均衡を補正するクラス重みを付けて、交差エントロピー損失で学習します。
5. 検証精度と混同行列を表示し、`models/*.pt` と `*_metrics.json` に保存します。

## 5. 誤差逆伝播と Adam による重み更新 — train.py 70〜78行目

```python
for ep in range(epochs):                         # データ全体を epochs 回くり返す
    perm = torch.randperm(len(ytr))              # 毎回順番をシャッフル
    for i in range(0, len(ytr), 128):            # 128個ずつのミニバッチ
        opt.zero_grad()                          # ① 前回の勾配を消す
        loss = loss_fn(model(Xtr[b]), ytr[b])    # ② 予測して損失を計算
        loss.backward()                          # ③ 誤差逆伝播で勾配を計算
        opt.step()                               # ④ Adamで重みを更新
```

**② 損失・交差エントロピー**: 正解クラスの予測確率を p とすると、損失は −log(p) です。p=0.9 なら損失は0.105、p=0.1 なら2.30です。正解に高い確率を付けるほど小さくなる量で、これを小さくするのが学習の目標です。`weight=` によって、数の少ない旋回クラスを間違えたときの損失を大きくしています。

**③ 誤差逆伝播**: 損失を各重みで微分した値、つまり「その重みを少し増やすと損失がどれだけ増えるか」を、出力層から入力層へ向かって **連鎖律** で順番に計算します。PyTorchは計算の過程を記録しているので、`loss.backward()` の1行で26,243個すべての勾配が求まります。

**④ Adam**: 基本は、勾配の逆方向に少しずつ動かす勾配降下法です。Adam はさらに、次の2つを重みごとに管理します。
- **勾配の移動平均・モーメンタム**: 過去の勾配の向きを平均して、ノイズでジグザグに動くのを抑えます。
- **勾配の2乗の移動平均**: よく大きく動く重みは歩幅を小さく、あまり動かない重みは歩幅を大きくします。

`lr=1e-3` は基本の歩幅である学習率です。`weight_decay=1e-4` は重みが大きくなりすぎないようにする正則化で、過学習を抑えます。

## 6. argmax 制御と soft 制御の違い — ai_driver.py 63〜79行目

MLP の出力が `P = [0.55, 0.40, 0.05]`、つまり前進55%・左40%・右5%だったとします。行動ごとの速度は common.py の14行目 `ACTION_TWIST` で決まっていて、前進が v=0.18・ω=0、左が v=0.02・ω=+0.9、右が v=0.02・ω=−0.9 です。

| 方式 | 計算 | この例での指令 |
|---|---|---|
| **argmax** 既定 | 最も確率の高い行動の速度をそのまま使う | v=0.18, ω=0。全速で直進 |
| **soft** `--control soft` | 確率で速度を重み付け平均する。v = Σ Pᵢ·vᵢ、ω = Σ Pᵢ·ωᵢ | v=0.55×0.18+0.40×0.02+0.05×0.02 = **0.108**、ω=0.40×0.9−0.05×0.9 = **+0.315** |

- argmax は判断がはっきりしていますが、確率が拮抗して迷っているときでも全速で動き、前進と旋回が切り替わるときの動きがカクカクします。
- soft は、迷っているほど自動的に減速し、ゆるやかに曲がります。ただし、左と右が半々のときは ω が打ち消し合って0になり、前進確率も低いため、**ほとんど止まってしまう** おそれがあります。これが soft 制御の弱点です。

## 7. DAgger が悪化した原因：観測事実と仮説

### 観測事実
- 教師v1のデータ1,176件だけで学習した v1 BC は、初期位置をそろえた120秒の走行で、衝突イベントが0回でした。
- そこに、v1モデルが運転したときの状態863件を教師v1でラベル付けして追加した v1+DAgger は、検証精度が91.1%から93.9%に上がったにもかかわらず、同じ条件の走行で **衝突イベントが6回** 起き、教師一致率は72%でした。比較は各1回ずつです。
- 6回のうち4回は左下の柱付近、2回は外周の壁付近で起きました。
- 衝突イベントの直前には、前進確率≈1.0のまま最小距離が縮んでいく場面と、左旋回確率≈1.0でその場旋回しているのに最小距離が0.20mから0.12mへ縮む場面がありました。
- 初期位置をそろえていない初回の DAgger 走行では、外周の壁際で衝突イベントが12回ありました。
- 教師v1が判断に使う角度は前方±60°だけで、**真横を見ていません**。
- ログには最小距離の値だけを記録し、方向は記録していません。そのため、どの方向の障害物に近づいたかはログからはわかりません。
- DAgger で集めた状態863件は、その後に教師v2で再ラベルされ、最終採用モデルの学習データにも含まれています。悪化したのは、v1のラベルのまま追加学習した条件です。

### 仮説
1. **教師の欠陥が DAgger で増幅された**: 教師v1は横の壁が近くても前進を正解とするため、壁際の状態では「壁すれすれでも前進」が正解になります。DAgger で壁際の状態が多く追加された結果、モデルがそのような判断を強く学んだと考えています。
2. **旋回時の車体の振れ**: LiDARが回転中心からずれていることと、旋回中も v=0.02m/s で少し前進することから、壁際でその場旋回すると車体が壁に近づきます。教師v1はこれを考慮していません。
3. **試行回数の不足**: 比較はそれぞれ1回ずつです。LiDARノイズで軌跡が変わるため、偶然の差である可能性を否定できません。

### 検証できていない点
- 最小距離の方向を記録していないため、仮説1を直接確かめられません。
- 教師v2のラベルで DAgger を行う条件を試していないため、教師を直した効果と DAgger の効果を分けられていません。
- DAgger の条件を複数回試していません。

## 8. 実験結果から言えること・言えないこと

### 言えること
- MLP の推論だけで、turtlebot3_world 内を一定時間、衝突イベントなしで走行できる場合があります。ただし、今回の評価条件と回数の範囲内での話です。
- オフラインの検証精度が高くても、走行性能が良いとは限りません。v1+DAgger がその例で、閉ループの評価が必要です。
- 教師ルールの設計は、模倣学習した方策の振る舞いに大きく影響します。

### 言えないこと
- **AIが教師ルールより優れていること**。ラベルが教師由来なので、原理的に教師が性能の上限の目安になります。最接近距離などで教師を上回った回があっても、試行回数が少なく偶然の範囲内です。
- **別の環境や実機での性能**。家や迷路、動く障害物がある環境では試していません。
- **長時間の安全性**。各試行は90〜150秒です。
- **物理的に一度も接触していないこと**。衝突イベントは LiDAR の距離が0.13m未満になった回数で、接触センサで判定していません。LiDARより低い位置にある物体など、死角での接触は検出できません。
- **統計的に有意な差**。各条件は3回、一部は1回で、初期位置も1か所だけです。さらに、一括評価12回のうち2回は `/reset_world` が効かず、別の位置から始まっていました。
