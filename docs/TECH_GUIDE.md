## 2. LiDARのデータが MLP に入るまで（前処理）

### 2.1 生データ
`/scan` トピックの `sensor_msgs/LaserScan` には、360個の距離 `ranges[0..359]` が入っています（Gazeboの設定は5Hz、360サンプル、0.12〜3.5m、ノイズσ=0.01m）。
- `ranges[0]` が **正面**、インデックスが増えるほど **反時計回り（左）**。`ranges[90]` が真左、`ranges[270]` が真右です。
- 3.5mより遠い方向や何もない方向は `inf`（無限大）になります。

### 2.2 `clean_ranges`（common.py 21行目）
`inf`、`nan`、0以下の値を 3.5m に置き換え、0〜3.5m の範囲に収めます。ニューラルネットは `inf` を扱えないためです。

### 2.3 `scan_to_features`（common.py 28行目）
360本をそのまま入力にせず、**5°ごとの72個の扇形（セクタ）に分け、各セクタの「最小距離」**をとります。
- 最小値をとる理由: 衝突回避では「その方向で一番近い障害物」が重要だからです。
- 最後に 3.5 で割って **0〜1 に正規化**します（ニューラルネットは入力の大きさがそろっている方が学習しやすい）。
- 結果は **72次元のベクトル**です。例: `feat[0]` = 0〜5°方向の最小距離÷3.5。
- 24セクタ（15°刻み、v1モデル用）にも対応しています。どちらを使うかはモデルファイルに保存された `n_sectors` で決まります（policy.py 13行目）。

```
360本の距離 ──clean_ranges──► 0〜3.5m の360本 ──scan_to_features──► 72個の最小距離 ÷3.5 ──► MLPへ
```

## 3. ネットワーク構造：72-128-128-3（common.py 98行目 `PolicyMLP`）

```python
nn.Sequential(
    nn.Linear(72, 128), nn.ReLU(),     # 第1層: 72個の入力 → 128個のニューロン
    nn.Linear(128, 128), nn.ReLU(),    # 第2層: 128 → 128
    nn.Linear(128, 3),                 # 出力層: 128 → 3（前進・左・右の「スコア」）
)
```

- **Linear（全結合層）**: 各出力ニューロンは「入力すべてに重みを掛けて足し、バイアスを足したもの」です（`y = Wx + b`）。第1層の重み W は 128×72 個あります。
- **ReLU**: `max(0, x)`。負の値を0にする非線形関数です。これがないと、何層重ねても1層の線形変換と同じになり、「前方が近い **かつ** 右も近いなら左」のような組み合わせ判断を表現できません。
- **出力（ロジット）**: 3つの実数（スコア）。`policy.py` 23行目で **softmax** を適用し、合計1の確率 `[P(前進), P(左), P(右)]` に変換します。
- パラメータ数: 72×128+128 + 128×128+128 + 128×3+3 = **26,243個**。小さなモデルなので、CPUで1ms未満で推論できます。

## 4. 教師データの収集と模倣学習の仕組み

### 4.1 教師（エキスパート）＝ルール
`teacher_action_v2`（common.py 71行目）は人間が書いたif文で、LiDARから「正解の行動」を決めます。
1. 前方±30°の最小距離 > 0.55m、かつ斜め前（30〜75°、−75〜−30°）> 0.35m なら前進候補
   - ただし真横（75〜105°）に 0.22m 未満の壁があれば、反対側へ旋回
2. それ以外は、左右20〜100°の平均距離が大きい方へ旋回

**重要**: 学習データの正解ラベルは、すべてこのルールで自動生成されています。人間が操作したデータではありません。

### 4.2 データ収集 `collect_data.py`
`on_scan`（59行目）が `/scan` を受信するたびに（約5Hz）、次の処理を行います。
1. 生LiDAR（360本）と、教師ルールが出した**ラベル**を記録する
2. 実際にロボットを動かす行動を決める:
   - 通常は教師の行動をそのまま実行（`--policy teacher`）
   - 確率 ε（`--epsilon`、74行目）で**わざとランダムな行動**を1〜4ステップ続ける。これにより、教師だけでは訪れない「少し危ない状態」もデータに入り、その状態に対する正しい行動を学べます
   - DAggerモード（`--policy student`、78行目）では、学習済みモデルが運転し、教師はラベルを付けるだけ（確率 β で教師が運転）
3. 障害物に0.13m未満まで近づいたら、または15秒間動けなかったら、`/reset_world` で初期位置へ戻す（93, 99行目）

保存されるもの（`data/*.npz`）: `X`（収集時の特徴量）、`y`（教師ラベル）、`raw`（生LiDAR 360本）。
**`raw` を保存してあるので、後から教師ルールを変えてもラベルを付け直せます**（`train.py --relabel`）。

### 4.3 模倣学習（Behavior Cloning）
「LiDAR → 教師の行動」という対応を、**教師あり学習の分類問題**として学びます。画像分類（写真→猫/犬）と同じ枠組みで、入力が LiDAR、クラスが3つの行動になっているだけです。

`train.py` の流れ:
1. `raw` から特徴量を計算し、`--relabel` なら教師ルールでラベルを付け直す
2. 全データをシャッフルし、**80%を学習用、20%を検証用**に分ける（42行目）。検証用は学習に使わず、「初めて見るデータに対する正解率」を測るために使う
3. `--augment` のとき、学習用だけを増やす（51〜55行目）
   - **左右反転** `np.roll(r[::-1], 1)`: 角度θのデータを−θへ移す。左右を入れ替えたスキャンに対して教師ルールでラベルを付け直す
   - **ノイズ付加** `rng.normal(0, 0.02, …)`: 距離に±2cm程度のランダムな揺らぎを加える
4. クラス重み（前進が多く旋回が少ない不均衡を補正）を付けた交差エントロピー損失で学習する
5. 検証精度と混同行列を表示し、`models/*.pt` と `*_metrics.json` に保存する

## 5. 誤差逆伝播と Adam による重み更新（train.py 70〜78行目）

```python
for ep in range(epochs):                         # データ全体を epochs 回くり返す
    perm = torch.randperm(len(ytr))              # 毎回順番をシャッフル
    for i in range(0, len(ytr), 128):            # 128個ずつのミニバッチ
        opt.zero_grad()                          # ① 前回の勾配を消す
        loss = loss_fn(model(Xtr[b]), ytr[b])    # ② 予測して損失を計算
        loss.backward()                          # ③ 誤差逆伝播で勾配を計算
        opt.step()                               # ④ Adamで重みを更新
```

**② 損失（交差エントロピー）**: 正解クラスの予測確率を p とすると、損失は −log(p) です。p=0.9 なら損失は0.105、p=0.1 なら2.30 です。「正解に高い確率を付けるほど損失が小さい」量であり、これを小さくするのが学習の目標です。`weight=` によって、数の少ない旋回クラスを間違えたときの損失を大きくしています。

**③ 誤差逆伝播（backpropagation）**: 損失を各重みで微分した値（勾配）＝「その重みを少し増やすと損失がどれだけ増えるか」を、出力層から入力層へ向かって**連鎖律**で順番に計算します。PyTorchは計算の過程を記録しているので、`loss.backward()` の1行で26,243個すべての勾配が求まります。

**④ Adam**: 基本は「勾配の逆方向に少し動かす」（勾配降下法）ですが、Adamは次の2つを重みごとに管理します。
- 勾配の移動平均（**モーメンタム**）: 過去の勾配の向きを平均して、ノイズでジグザグに動くのを抑えます
- 勾配の2乗の移動平均: よく大きく動く重みは歩幅を小さく、あまり動かない重みは歩幅を大きくします

`lr=1e-3` は基本の歩幅（学習率）です。`weight_decay=1e-4` は重みが大きくなりすぎないようにする正則化で、過学習を抑えます。

## 6. argmax 制御と soft 制御の違い（ai_driver.py 63〜79行目）

MLP の出力が `P = [0.55, 0.40, 0.05]`（前進55%、左40%、右5%）だったとします。行動ごとの速度は `ACTION_TWIST`（common.py 14行目）で、前進が (v=0.18, ω=0)、左が (0.02, +0.9)、右が (0.02, −0.9) です。

| 方式 | 計算 | この例での指令 |
|---|---|---|
| **argmax**（既定） | 最も確率の高い行動の速度をそのまま使う | v=0.18, ω=0（全速で直進） |
| **soft** (`--control soft`) | 確率で速度を重み付け平均する: v = Σ Pᵢ·vᵢ, ω = Σ Pᵢ·ωᵢ | v=0.55×0.18+0.40×0.02+0.05×0.02 = **0.108**, ω=0.40×0.9−0.05×0.9 = **+0.315** |

- argmax は判断がはっきりしていますが、確率が拮抗している（迷っている）ときでも全速で動き、前進と旋回が切り替わるときの動きがカクカクします。
- soft は、迷っているほど自動的に減速し、ゆるやかに曲がります。ただし「左と右が半々」のときは ω が打ち消し合って0になり、前進確率も低いため、**ほとんど止まってしまう**おそれがあります。これは soft 制御の弱点です。

## 7. DAgger が失敗した原因（観測事実と仮説の区別）

### 観測事実（ログから確認できること）
- v1 BC（教師v1のデータ1,176件だけで学習）は、120秒の走行で衝突イベント0回だった（同じ初期位置から1回）。
- v1+DAgger（上記に、v1モデルが運転したときの状態863件を教師v1でラベル付けして追加）は、検証精度が 91.1% → 93.9% に上がったにもかかわらず、同じ条件の走行で**衝突イベントが6回**、教師一致率は72%だった（1回）。
- その6回の位置は、4回が左下の柱付近（x≈−1.0, y≈−1.5）、2回が外周の壁付近だった（`logs/run_20261101_100433.csv`）。
- 衝突イベントの直前のログには、①前進確率≈1.0のまま最小距離が縮んでいく場面と、②LEFT確率≈1.0でその場旋回しているのに最小距離が0.20→0.12mへ縮む場面があった。
- 初期位置をそろえていない初回のDAgger走行（`run_20261101_095920`）では、外周の壁際（y≈1.6〜2.2）で衝突イベントが12回あった。
- 教師v1は、判断に使う角度範囲が前方±60°だけで、**真横（60°より外側）を見ていない**（コードで確認できる事実）。
- ログには最小距離の「値」だけを記録し、「方向」は記録していない。そのため、どの方向の障害物に近づいたかはログからはわからない。

### 仮説（検証はしていない）
1. **教師の欠陥がDAggerで増幅された**: 教師v1は横の壁が近くても前進を正解とするため、壁際の状態のデータでは「壁すれすれでも前進」が正解になる。DAggerで壁際の状態が多く追加された結果、モデルはそのような判断を強く学んだ。
2. **旋回時の車体の振れ**: LiDARが回転中心からずれていること、旋回中も v=0.02m/s で少し前進することから、壁際でのその場旋回では車体が壁に近づく。教師v1はこれを考慮していない。
3. **試行回数の不足**: 比較はそれぞれ1回ずつである。LiDARノイズで軌跡が変わるため、偶然の差である可能性を否定できない。

### この仮説の検証として不足している点
- 最小距離の方向を記録していないため、仮説1（横の障害物）を直接確かめられない。
- 教師v2のラベルで DAgger を行った条件を試していない（教師を直したことの効果と、DAggerの効果を分けられていない）。
- DAggerの条件を複数回試していない。

## 8. 実験結果から言えること・言えないこと

### 言えること
- MLPの推論だけで、turtlebot3_world 内を一定時間、衝突イベントなしで走行できる場合がある（評価条件と回数の範囲内で）。
- オフラインの検証精度が高くても、走行性能が良いとは限らない（v1+DAggerの例）。閉ループの評価が必要である。
- 教師ルールの設計が、模倣学習した方策の振る舞いに大きく影響する。

### 言えないこと
- 「AIが教師ルールより優れている」こと（ラベルが教師由来なので、原理的に教師が上限の目安になる。最接近距離などで上回った回があっても、試行回数が少なく偶然の範囲内）。
- 別の環境（家、迷路、動く障害物）や実機での性能。
- 長時間（数十分以上）の安全性。各試行は90〜120秒である。
- 「衝突0回」＝「物理的に一度も接触していない」こと。衝突イベントはLiDARの距離0.13m未満で定義しており、接触センサで判定していない。逆に、LiDARの死角（低い位置や、0.12m未満で値が無効になる範囲）での接触は検出できない。
- 統計的に有意な差。各条件3回（一部1回）であり、初期位置も1か所だけである。さらに一括評価12回のうち2回は `/reset_world` が効かず、別の位置から始まっていた（README「実験設計の監査」）。
