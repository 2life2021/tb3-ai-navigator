## 2. 何をAIが学習し、何を人間が決めたか

本作品で **AIが学習によって決めたのは、MLPの重みとバイアスだけ** です。それ以外の設定は、すべて人間が決めました。人間が決めた値は、コードの定数またはコマンドライン引数として記録されています。

### 2.1 AIが学習で決めたもの

| 決めたもの | 役割 | 決まり方 |
|---|---|---|
| **MLPの重みとバイアス** 26,243個 | LiDARの特徴量から、前進・左旋回・右旋回それぞれの確率を計算する式の係数 | 教師ラベルとの誤差が小さくなるように、誤差逆伝播と Adam で自動的に調整される |

### 2.2 人間が決めたもの：開発の流れの順

| 段階 | 決めたもの | 最終採用モデルの値 | 何に影響するか |
|---|---|---|---|
| **① タスクの設計** | 行動の種類と速度 `ACTION_TWIST` | 前進 v=0.18m/s ／ 左右 v=0.02m/s, ω=±0.9rad/s。全期間で変更なし | ロボットが取れる動きそのもの |
| **② 正解の定義** | 教師ルールの閾値 | 2.3 の表を参照 | **AIが「正しい」と学ぶ行動の基準**。AIの振る舞いを最も強く左右する |
| **③ 入力の作り方** | LiDARのまとめ方 | 5°ごとの72区間の最小距離を、3.5で割って0〜1にそろえる | AIが周囲をどの細かさで見るか |
| **④ データの集め方** | ランダム行動の確率 ε | 0.10、DAggerの回のみ0.05。ランダム行動は1〜4ステップ続ける | 危ない状態のデータがどれだけ含まれるか |
| | DAggerで教師が操作する確率 β | 0.3 | AI自身が運転した状態をどれだけ集めるか |
| | 収集時間 | 240秒・180秒・240秒の3回、計3,206件 | データの量 |
| | 収集中のリセット | 0.13mより近づくか、15秒間で0.10mしか動かなければ `/reset_world` | 衝突後の状態がデータに混ざるのを防ぐ |
| **⑤ 学習の設定** | モデルの大きさ | 隠れ層 128 × 2層 | 表現できる判断の複雑さ |
| | 学習の回数・進め方 | エポック150、バッチ128、Adam 学習率0.001、weight_decay 0.0001 | 学習がどこまで、どれだけ速く進むか |
| | 損失の重み | クラスの件数に反比例する重み | 件数の少ない旋回を軽視しないようにする |
| | データ拡張 | 左右反転と、σ=0.02m のノイズで学習データを10倍 | 未知の状態への強さ |
| | 検証データの割合と乱数シード | 20%・シード0 | 精度の測り方と、学習の再現性 |
| **⑥ 推論・制御** | 制御方式 | argmax。soft も選択可能 | 確率から速度指令への変換方法 |
| **⑦ 評価のルール** | 衝突イベントの基準 | LiDAR全周の最小距離が0.13m未満 | 何を「衝突」と数えるか |
| | 試行時間と回数 | 90秒 × 3回。時間は実時間で区切る | 評価の信頼性 |

### 2.3 教師ルールの閾値

| | 教師v1 `teacher_action_v1` | 教師v2 `teacher_action_v2` |
|---|---|---|
| 前方 | ±25° が 0.55m より遠い | ±30° が 0.55m より遠い |
| 斜め前 | 25〜60° が 0.30m より遠い | 30〜75° が 0.35m より遠い |
| 真横の確認 | なし | 75〜105° が 0.22m 未満なら、反対側へ旋回 |
| 旋回方向の決め方 | 20〜100° の平均距離が大きい側 | 同じ |

`common.py` の `teacher_action` は、現在 `teacher_action_v2` を指しています。今 `collect_data.py` でデータを集めると、ラベルは v2 になります。

### 2.4 特徴量の詳細

| 項目 | 値 |
|---|---|
| セクタ数 | v1系は24、v2_s72 と最終モデルは72。セクタ数はチェックポイントの `n_sectors` に保存され、値のない v1系は24として読み込まれる |
| セクタの配置 | 24セクタは正面を中心に±7.5°ずつ、72セクタは0°から5°刻み |
| 集約方法 | 各セクタの最小値を3.5で割る |

## 3. データの来歴：どの教師が、どの条件で集めたか

| データ | 運転していたもの | 保存されたラベル | ε | β | 時間 | 件数 | 前 / 左 / 右 | リセット | 開始位置 |
|---|---|---|---|---|---|---|---|---|---|
| `teacher.npz` | 教師v1 | 教師v1 | 0.10 | – | 240秒 | 1,176 | 1020 / 85 / 71 | 0回 | 記録なし |
| `dagger1.npz` | v1モデル。確率0.3で教師v1 | 教師v1 | 0.05 | 0.3 | 180秒 | 863 | 721 / 84 / 58 | 0回 | 記録なし |
| `teacher_v2.npz` | 教師v2 | 教師v2 | 0.10 | – | 240秒 | 1,167 | 717 / 233 / 217 | 1回 | 記録なし |

**この表から読み取れること**
- 教師v1のデータは前進が約87%を占め、旋回のデータが少なくなっています。真横を確認する教師v2では前進が約61%に下がり、旋回のデータが大きく増えました。
- 保存されるラベルは、実際に実行した行動ではなく、常にその時点の教師ルールの出力です。ランダム行動中や AI の運転中でも、ラベルは教師が付けています。
- 3つのファイルとも、生LiDAR 360本を `raw` として保存しています。**v2系のモデルはすべて `--relabel` で学習しており**、`teacher.npz` と `dagger1.npz` に保存された v1 のラベルは使わず、`raw` から教師v2でラベルを付け直しています。
- そのため、**最終採用モデルの学習データには、DAggerで集めた状態863件が教師v2のラベルで含まれています**。DAggerで悪化したのは「v1のラベルのまま追加学習した」条件です。DAggerの状態データが最終モデルにどれだけ寄与したかは、切り分けて評価していません。

## 4. モデルの来歴

| モデル | データ | ラベル | セクタ | 隠れ層 | エポック | 拡張 | 学習精度 | 検証精度 | 状態 |
|---|---|---|---|---|---|---|---|---|---|
| `policy.pt` v1 | teacher | 保存済みのv1 | 24 | 64 | 300 | なし | 96.8% | 91.1% | 公開 |
| `policy_dagger1.pt` | teacher + dagger1 | 保存済みのv1 | 24 | 64 | 300 | なし | 98.7% | 93.9% | 公開 |
| 最初の `policy_v2.pt` | teacher_v2 のみ | 保存済みのv2 | 24 | 64 | 300 | なし | 91.4% | 79.0% | 上書きされて現存しない |
| `policy_v2_s24.pt` | 3データ | v2で再ラベル | 24 | 128 | 600 | なし | 98.4% | 87.1% | 公開 |
| `policy_v2_s72.pt` | 3データ | v2で再ラベル | 72 | 128 | 600 | なし | 99.8% | 88.3% | 公開 |
| **`policy_v2_aug.pt`** | 3データ | v2で再ラベル | 72 | 128 | 150 | あり | 95.9% | 87.2% | **最終採用** |

「3データ」は `teacher.npz`・`dagger1.npz`・`teacher_v2.npz` の合計3,206件で、うち検証用が641件、学習用が2,565件です。学習精度は、拡張を含む学習用データに対する精度です。

**この表から読み取れること**
- v2_s24・v2_s72・v2_aug は同じデータ・同じシードなので、**検証用の641件はまったく同じ**です。この3つの検証精度は、同じ問題に対する比較になっています。
- v2系の拡張なしの2モデルは、学習精度が98.4%と99.8%で、検証精度より11ポイント以上高く、過学習の傾向があります。データ拡張をすると学習精度は95.9%に下がり、検証精度との差は8.7ポイントに縮まりました。走行では、このモデルが障害物から最も距離を保っていました。
- v1とDAggerは検証データが異なり、教師も異なるため、v2系とは精度を直接比較できません。

### 学習の決定性：再現性の証拠
上書きされた2つ目の `policy_v2.pt` と `policy_v2_s24.pt` は、同じ設定で、間に `train.py` の改修を挟んで別々に学習したものです。それでも、記録された**学習精度0.98441と検証精度0.87051が完全に一致**しています。このことから、少なくともこの環境では、同じデータ・設定・シードで学習すれば同じ結果が得られると考えられます。

## 5. 何が再現でき、何が再現できないか

| 対象 | 再現性 | 理由 |
|---|---|---|
| 学習 | **高い** | numpy と PyTorch のシードを固定しており、上の一致例がある |
| データ収集 | 低い | 乱数シードを固定しておらず、LiDARノイズ・通信のタイミング・記録していない開始位置によって変わる |
| 走行評価 | 中程度 | 開始位置は `/reset_world` でそろえましたが、12回中2回は失敗。ノイズとタイミングによって軌跡は毎回変わり、向きも記録していない |
| 実行時間 | 注意が必要 | すべて実時間で区切っているため、シミュレーション速度が変わると同じ「90秒」でも走行内容が変わる |

### 各モデルを再現するコマンド

```bash
# v1。保存されている v1 ラベルをそのまま使うため、--relabel は付けない
python3 scripts/train.py data/teacher.npz --out models/policy.pt
# v1 + DAgger
python3 scripts/train.py data/teacher.npz data/dagger1.npz --out models/policy_dagger1.pt
# v2_s24 / v2_s72
python3 scripts/train.py data/teacher.npz data/dagger1.npz data/teacher_v2.npz --relabel --sectors 24 --hidden 128 --epochs 600 --out models/policy_v2_s24.pt
python3 scripts/train.py data/teacher.npz data/dagger1.npz data/teacher_v2.npz --relabel --sectors 72 --hidden 128 --epochs 600 --out models/policy_v2_s72.pt
# 最終モデル
python3 scripts/train.py data/teacher.npz data/dagger1.npz data/teacher_v2.npz --relabel --sectors 72 --augment 4 --hidden 128 --epochs 150 --out models/policy_v2_aug.pt
```

v1系のデータを新しく集め直す場合は、`common.py` の `teacher_action = teacher_action_v2` を `teacher_action_v1` に変える必要があります。

## 6. 再現性を高めるために必要なこと

1. データ収集の開始位置・向き・乱数シードを記録する
2. 走行評価で向きを記録し、リセットの成否を確認する
3. 実時間ではなく、シミュレーション時間で試行時間を区切る
4. モデルとログのファイル名に日時や設定を含め、上書きを防ぐ
