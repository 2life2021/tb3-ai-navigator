# Physical AI課題制作を通して得た学びと今後の課題

今回の課題では、ROS 2と機械学習を利用したTurtleBot3の自律走行システムを制作した。その過程で、開発環境の構造、ロボットの通信・制御、ニューラルネットワークの学習原理について理解を深めた。

## 1. 開発環境の階層構造

最も大きな学びは、開発環境を構成する各技術の役割と階層関係であった。

OSはコンピュータ全体の動作を管理し、その中核である**カーネル**がプロセスやメモリ、ハードウェア資源などを管理していることを学んだ。一方、PowerShellやBashなどの**シェル**は、ユーザーがコマンドを通じてOSやプログラムを操作するためのインターフェースであると理解した。

また、Dockerはコンテナによって実行環境を管理する仕組みであり、コンテナは原則として独立したカーネルを持たず、ホスト側から提供されるカーネルを利用することを学んだ。今回のWindows上で動作するLinuxコンテナも、Linuxカーネルを利用できる仮想化環境を介して実行されていると理解した。

さらに、**ROS 2はノード間の通信を担うミドルウェア、Gazeboはロボットの運動を再現する物理シミュレータ**であり、これらはOSやシェルとは異なる階層に分類されることを学んだ。

このように、開発環境を単なるソフトウェアの集合ではなく、異なる役割を持つ技術が階層的に連携するシステムとして理解できた。

## 2. ROS 2の通信構造

ROS 2では、**ノードが処理を担当する単位であり、トピックはノード間で情報を交換するための通信経路**であることを理解した。例えば、LiDARの観測情報は `/scan`、ロボットへの速度指令は `/cmd_vel` というトピックを通して送受信される。

また、Pythonの `self.on_scan` と `self.on_scan()` の違いも重要だと学んだ。前者はメソッドそのものを参照し、後者はメソッドを呼び出す。この違いから、センサー情報が届いた際に、事前に登録した処理が実行される**コールバック**の仕組みを理解できた。

さらに、`/odom` はロボットの位置や姿勢に関する推定情報を提供するが、その値には誤差が含まれる可能性があり、正確な自己位置を保証するものではないことを学んだ。

特に、**オドメトリによる位置推定と、LiDARによる障害物の認識は異なる機能**であると区別することが重要だと理解した。

## 3. ロボットの認識と制御

今回のAIでは、LiDARから取得した360方向の距離情報を5度ごとの72区間に分割し、各区間の最短距離を抽出することで、72次元の特徴量に圧縮した。360を72で割ると、1区間はちょうど5度になる。

この処理により、入力する情報量を削減しながら、各方向で最も近い障害物の情報を残せることを学んだ。一方で、圧縮によって元の観測情報の一部は失われることも理解した。

また、今回の**MLPへの入力は `/scan` に由来するLiDAR情報のみであり、`/odom` による位置・姿勢情報は使用していない**。したがって、今回のシステムは目的地までの経路を計画するナビゲーションではなく、現在の周囲状況に応じて前進・左旋回・右旋回を選択し、障害物との衝突を回避しようとする反応型の制御システムである。

ここから、**障害物を回避する能力と、地図や自己位置を利用して目的地に到達する能力は異なる**と理解した。

## 4. 機械学習の構造と学習原理

### MLP・ニューロン・パラメータ

今回のMLPは、72次元の入力から128個・128個のニューロンを持つ隠れ層を経て、3種類の行動を出力する **72 → 128 → 128 → 3** の構造である。

ここで、128というニューロン数は人間が設定した**ハイパーパラメータ**であり、各ニューロンの計算に使用される重みとバイアスは、学習によって調整される**モデルパラメータ**であることを学んだ。今回のモデルには、モデルパラメータが合計26,243個存在する。

各ニューロンは入力の重み付き和とバイアスを計算し、活性化関数を通して次の層に情報を渡すことを理解した。

隠れ層で生成される128個の中間特徴量は、必ずしも人間が解釈できる意味や、物理量同士の相関を表しているわけではなく、教師の行動を予測する際の損失が小さくなるように形成された、数学的な中間表現であると理解した。

また、72個の入力から128個の特徴量を生成しても、元の入力に存在しない独立した情報が増えるわけではなく、既存の情報を異なる形に変換し、より複雑な判断規則を表現できるようにしていることを学んだ。

### 教師データとデータ拡張

今回のAIは、人間が設計したルールベースの教師の行動を模倣する**行動クローニング**を中心として学習した。

学習データ3,206件は手動で個別に作成したものではなく、Gazebo上でロボットを自動走行させ、LiDAR情報と教師の判断を記録して収集した。さらに、学習用に分割した2,565件のデータに左右反転や距離ノイズを加え、25,650件に拡張した。

ここで増やしたのは、MLPのニューロン数ではなく、**教師ラベル付きの学習データ**である。つまり、ニューロン数はモデルの構造を決める設定、重み・バイアスは学習する対象、データ拡張は学習材料を増やす操作であり、それぞれ役割が異なることを理解した。

### 損失関数と学習

MLPが出力する3つの値はロジットと呼ばれ、そのまま確率を意味するものではないことを学んだ。Softmax関数によって合計1の確率分布に変換できるが、**その値が現実の成功確率として正確である保証はない**ことも理解した。

今回の学習では、ロジットと教師ラベルから交差エントロピー損失を計算し、誤差逆伝播によって各パラメータの勾配を求め、Adamを用いて重みとバイアスを更新した。PyTorchの交差エントロピー損失には、Softmaxに相当する処理が内部に含まれていることも学んだ。

また、バッチサイズや学習率は人間が設定するハイパーパラメータであり、重み・バイアスとは異なると理解した。

### MLPを利用する意義と評価の限界

今回の教師ルールは、それ自体で障害物回避を実行できる。それでもMLPを用いた意義は、**人間が設計した判断規則を、データからニューラルネットワークに学習させる仕組みを実装・検証すること**にあると考えた。

ただし、MLPが教師より優れているとは限らず、モデルの表現力が高いことと未知環境への汎化性能が高いことも同義ではないと学んだ。

今回得られた検証精度87.2%は、**教師ルールとの行動一致率であり、障害物回避の成功率ではない**と理解した。また、学習データと検証データは同じ収集データから分割しているため、観測内容が似ている可能性がある。したがって、シミュレーションでの成功や教師との一致率だけで、未知の障害物配置や実環境でも適切に動作すると判断することはできないと学んだ。

## 5. 限界・課題・改善案

今回のシステムでは、Gazebo上でLiDARを利用した障害物回避と、その判断をMLPに模倣させる仕組みを実現した。

一方、実環境への応用や機械学習モデルの有効性を検証するうえでは、以下の限界と課題が残されている。

### ① 未知環境への汎化性能

**限界：** 今回の評価は主に特定のシミュレーション環境におけるものであり、未知の障害物配置でも同様に動作するとは限らない。

**課題：** 学習データと検証データは同じ走行記録からランダムに分割しているため、互いに類似した観測が含まれる可能性がある。結果として、検証精度が未知環境での性能を十分に反映していないおそれがある。

**改善案：** 学習用と評価用で障害物の配置や初期位置を明確に分離し、未経験の環境における走行成功率、障害物との最短距離、停止・接触回数などを比較する。

### ② 教師ルールへの依存

**限界：** MLPが学習する正解は人間が設計した教師ルールの判断であり、必ずしも最適な行動とは限らない。

**課題：** 教師ルールが不適切な判断をする状況では、その判断をMLPも模倣する可能性がある。また、MLPを導入することで教師より性能が向上したとは確認できていない。

**改善案：** 教師ルール自体を改善するとともに、人間の操縦データや、衝突回避以外の評価基準を利用した学習方法を検討する。また、教師とMLPを同一条件で比較し、MLPを利用する利点を定量的に検証する。

### ③ 自己位置推定と経路計画の欠如

**限界：** 今回のMLPはLiDAR情報のみを入力としており、自己位置や目的地を考慮した行動選択は行わない。

**課題：** 現在の障害物を回避できても、目的地への到達や効率的な経路選択を保証できない。また、オドメトリには誤差が生じ得るため、単に `/odom` を入力に追加するだけでは正確な自己位置が得られるわけではない。

**改善案：** SLAMや自己位置推定、経路計画の仕組みを導入する。さらに、推定した自己位置や目標地点の情報を制御に利用することで、単純な障害物回避から目的地への自律移動へ発展させる。

### ④ モデル構造と特徴量の妥当性

**限界：** 今回の入力72次元、隠れ層128・128という構造が、最適であるとは確認できていない。

**課題：** ニューロン数や特徴量数を増やすと表現力は高まる可能性があるが、学習データへの過適合や計算量の増加につながる場合もある。また、5度ごとの最短距離への圧縮では、元の距離情報の一部が失われる。

**改善案：** 入力次元を36・72・360、隠れ層の幅を64・128・256などに変更し、検証精度だけでなく、未知環境での走行性能や推論速度も比較する。これにより、モデルの複雑さと性能の関係を検証する。

### ⑤ 評価指標と実験条件の不足

**限界：** 検証精度87.2%だけでは、実際の障害物回避性能や安全性を十分に評価できない。

**課題：** 教師との行動不一致には、危険な前進と不要な旋回など、影響の異なるものが含まれる。また、今回の走行評価は試行回数が限られ、初期状態のリセットにも失敗した試行があったため、結果の信頼性を十分に検証できていない。

**改善案：** 実験の初期条件と乱数を管理し、試行回数を増やす。衝突の有無、最短障害物距離、走行距離、停止時間などを記録し、平均値だけでなく結果のばらつきも比較する。また、危険な行動の誤分類を重点的に評価する。

### ⑥ 実機への適用と再現性

**限界：** 今回の動作確認はシミュレーション上で行っており、実機で同じ性能を発揮できるとは限らない。

**課題：** 実機ではセンサーの測定誤差、車輪の滑り、通信遅延、シミュレーションと現実の物理特性の違いなどが生じる。また、第三者が同じ実験を再現するには、コードだけでなく環境構築や実験条件の共有も必要になる。

**改善案：** センサーノイズや摩擦条件を変えたシミュレーション実験を行い、実環境との差に対する頑健性を確認する。そのうえで、安全対策を設けた実機試験へ段階的に移行する。また、Docker環境、依存ライブラリ、学習条件、実験手順をGitHub上に明示し、第三者による再現性を高める。

## 6. 総括

今回の最大の学びは、ロボットの自律走行を単一のAIの働きとしてではなく、**開発環境・通信・センシング・制御・機械学習が階層的に連携するシステム**として理解できたことである。

また、モデル構造と学習パラメータ、教師データとデータ拡張、障害物回避とナビゲーション、教師との一致率と実際の成功率など、似ている概念を明確に区別する重要性を学んだ。

特に、**何を入力し、何を正解として学習し、どのような指標で評価しているのかを正確に把握すること**が、機械学習システムの仕組みと限界を理解するうえで不可欠だと実感した。

今後は、未知環境における評価の独立性を高めるとともに、モデル構造や教師ルールの改善を検証する必要があると考えている。さらに、自己位置推定や経路計画を導入することで、現在の反応型障害物回避から、より高度な自律移動システムへ発展させることが課題である。

## 7. 今後の研究方針

今後は、単にモデルの分類精度を向上させるのではなく、**実際の目的である安全な障害物回避に対して、機械学習がどの程度有効なのか**を検証したい。

特に、教師ルールとMLPの走行性能を同一条件で比較するとともに、未知の障害物配置における汎化性能を評価する。また、入力次元や隠れ層の構造を変更することで、モデルの複雑さと実際の制御性能の関係を明らかにしたい。

これにより、機械学習を導入すること自体を目的とするのではなく、**どのような条件で、なぜ機械学習が有効になるのか**を検証することを今後の課題とする。
