# 開発記録 — 問題 → 原因 → 修正 → 結果

開発中に起きた問題と、その対処を時系列でまとめます。原因は、ログや実行結果で **確認済み** のもの、**推定** にとどまるもの、**未解明** のものに分けて書いています。

---

## 1. 学習・推論・制御に関わる変更

### A1. teleop が速度指令を送り続けていた
- **問題**: 環境を調べると、`teleop_keyboard` が `/cmd_vel` にゼロ速度を約10Hzで送り続けていました。
- **原因・確認済み**: 送信元は teleop の1つだけで、このままでは AI の指令と競合します。
- **修正**: 了承を得て teleop を停止しました。Gazebo は停止していません。
- **結果**: 停止後、`/cmd_vel` に何も流れていないことを確認しました。

### A2. 試行ごとに開始位置が違い、比較が不公平だった
- **問題**: v1+DAgger の最初の走行で衝突イベントが12回ありましたが、v1 とは開始位置が違っていました。
- **原因・確認済み**: 各試行が、前回の走行が終わった位置から始まっていました。
- **修正**: 走行開始時に `/reset_world` で初期位置に戻す `--reset` を、`ai_driver.py` に追加しました。
- **結果**: 以後の試行は (-2.0, -0.5) から始まるようになりました。ただし、一括評価では12回中2回失敗しています（A11）。

### A3. リセットを追加したら、起動時にエラーで落ちた
- **問題**: `--reset` を付けると、`AttributeError: 'AIDriver' object has no attribute 'start'` で落ちました。
- **原因・確認済み**: 初期化の途中でサービスの応答を待ったため、すでに登録していた `/scan` のコールバックが、初期化が終わる前に実行されていました。
- **修正**: リセット処理を、`/scan` の購読を登録するより前に移しました。
- **結果**: 正常に動作するようになりました。

### A4. DAgger を加えたら、検証精度は上がったのに走行が悪化した
- **問題**: 開始位置をそろえても、v1+DAgger は衝突イベントが6回ありました。v1 は0回です。検証精度は v1 の91.1%より高い93.9%でした。
- **原因・推定**: 教師v1が真横を見ていないため、障害物の近くで「前進」を正解とするラベルが、DAgger で増えた近距離の状態データによって強化されたと考えています。ログに障害物の方向がないため、直接は確かめられていません。各条件1回ずつの比較です。
- **修正**: 真横の確認を加えた教師v2 `teacher_action_v2` を作りました。
- **結果**: 教師自身の走行で、最接近距離が0.198mから0.234mに広がりました。

### A5. 最初の v2 モデルの検証精度が低かった
- **問題**: 教師v2のデータ1,167件だけで学習したモデルは、検証精度が79.0%でした。
- **原因・推定**: 教師v2は判断が細かく、旋回の学習が難しくなったのに対して、約1,100件というデータ量と、64という隠れ層の幅が足りなかったと考えています。
- **修正**: 保存してあった生LiDARから過去の全データ3,206件を教師v2で再ラベルする `--relabel` を新設し、隠れ層を128、エポック数を600にしました。
- **結果**: 検証精度は87.1%になりました。

### A6. 120秒の指定なのに、290秒かかった
- **問題**: 最初の v2 モデルの走行が、`--duration 120` なのに290.8秒かかりました。この間 scan は252回しか届かず、約0.9Hzでした。
- **原因・未解明**: 直後に計測した `/scan` は4.86Hzで正常でした。一時的なホストの負荷が考えられますが、特定できていません。
- **修正**: 予防策として、推論側の PyTorch を1スレッドで動かすようにしました。効果は検証していません。
- **結果**: 以後の走行では再発していません。

### A7. 24セクタでは精度が頭打ちになった
- **問題**: 検証精度が約87%で頭打ちになり、学習精度98%との差が大きいままでした。
- **原因・推定**: 教師が使う角度の境界である30°・75°・105°と、15°刻みのセクタの境界がずれているため、同じ特徴量に異なるラベルが付く状態が生じていると考えています。
- **修正**: 5°刻みの72セクタを選べるようにしました。境界が5°の倍数になり、教師の角度とそろいます。
- **結果**: 同じ検証データで、87.1%から88.3%に上がりました。改善はわずかでした。

### A8. モデルによって入力の次元が違うと、取り違えるおそれがあった
- **問題**: 24セクタと72セクタのモデルが混在すると、推論側で特徴量の次元を間違えるおそれがありました。
- **原因・設計上の問題**: 当初は、呼び出し側で特徴量を計算してからモデルに渡していました。
- **修正**: セクタ数をモデルファイルに保存し、推論側 `predict_from_scan` が自分で特徴量を計算するようにしました。セクタ数を持たない古い v1 のモデルは、24として読み込みます。
- **結果**: 24次元の v1 と72次元の v2_s72 の両方で推論できることを確認しました。

### A9. 72セクタでも過学習ぎみだった
- **問題**: 学習精度99.8%に対して、検証精度は88.3%でした。
- **原因・推定**: 約2,600件では、閾値付近の判断を汎化させるにはデータが足りないと考えています。
- **修正**: 左右反転と σ=2cm のノイズを加えたスキャンを教師v2で再ラベルし、学習データを10倍にしました。エポック数は150にしました。
- **結果**: 検証精度は87.2%で上がりませんでしたが、学習精度は95.9%になり、差は縮まりました。1回の予備走行で最接近距離が0.246mと障害物から最も離れていたため、最終採用としました。

### A10. argmax では、迷っていても全速で動く
- **問題**: argmax 制御では、確率が拮抗していても全速で前進し、前進と旋回が急に切り替わります。
- **原因**: 最大確率の行動だけを選ぶため、確率の大きさの情報を使わないという制御方式の性質です。
- **修正**: 確率で速度を重み付け平均する `--control soft` を追加しました。モデルや学習は変えていません。
- **結果**: 一括評価では衝突イベント0回で、argmax と同程度でした。リセットに失敗した試行が含まれるため、優劣は判断できません。

### A11. 一括評価の2回で、リセットが効いていなかった
- **問題**: 一括評価12回のうち2回で、開始位置が初期位置に戻っていませんでした。
- **原因・確認済み**: 開始位置のログで判明しました。コードはサービス呼び出しの成否を確認しておらず、失敗に気づけませんでした。失敗そのものの原因は、表示するログを絞っていたため不明です。
- **修正**: 提出を優先し、コードは修正していません。README と説明資料の監査に明記し、該当する試行を図で区別しました。

### A12. 教師一致率の基準が途中で変わった
- **問題**: 評価指標である教師一致率の基準が、途中で変わっていました。
- **原因・確認済み**: `teacher_action` を v1 から v2 に切り替えたため、それ以降は v1系のモデルの一致率も教師v2に対して計算されています。
- **修正**: 表の中で、どちらの教師との一致率かを明記しました。

### 制御部分は変わったか
- 行動ごとの速度 `ACTION_TWIST` は、最初から最後まで変えていません。
- 一括評価の後に `ai_driver.py` に加えたのは、可視化用トピック `/ai_nav/probs` の送信などだけで、行動の決定と速度指令の計算は変わっていません。

## 2. この記録から得た学び

1. **オフラインの検証精度と、閉ループの走行性能は別物だと学びました**。検証精度が最も高かった v1+DAgger の93.9%が、走行では最も悪い結果でした（A4）。逆に、データ拡張は検証精度を上げませんでしたが、走行では障害物から距離を保つようになりました（A9）。
2. **比較条件をそろえることの難しさを学びました**。開始位置（A2・A11）、評価指標の基準（A12）、シミュレーション速度（A6）など、気づかないうちに条件が変わる要因が多くありました。どれも、ログを残していたから後で気づけたものです。
3. **ラベルの定義こそが、最も重要な人間の設計だと理解しました**。教師の閾値は学習されない人間の設計であり、モデルの振る舞いを直接決めます（A4・A7）。生データを残しておいたことで、ラベルの定義を変えても再走行せずに済みました（A5）。
4. **成否を確認しないコードは、失敗を見えなくすると学びました**。`/reset_world` の成否を確認していなかったため、失敗に後から気づきました（A11）。また、表示するログを絞っていたため、失敗の原因も追えませんでした。
